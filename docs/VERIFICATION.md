## Scenarios

### `v01-repo-recon` — Repository reconnaissance

Locate code across a repository before touching it, which is the first move of nearly every session.

**Bridge defect this scenario is built to catch**: Large tool_result payloads truncated or re-encoded in transit; multi-call turns reordered so the model cites a path it never read.

Judged on:
- A search tool (Glob, Grep or Bash) was actually used.
- The answer names the planted file, not either decoy.
- Every tool_use in the transcript has a matching tool_result.
- result carries a stop_reason and non-zero usage, and modelUsage names the expected backend.

### `v02-surgical-edit` — Surgical edit and file creation

Change exactly what was asked and nothing else, then create a new file. The edit contract is byte-level.

**Bridge defect this scenario is built to catch**: Whitespace or newline normalisation in the tool_use payload makes Edit's exact-match fail, or silently matches the wrong line.

Judged on:
- The second marked line holds the new value.
- The first and third marked lines are byte-for-byte unchanged.
- The requested new file exists with the requested export.
- The Edit tool was used; the file was not rewritten wholesale.

### `v03-test-fix-loop` — Failing test diagnose and fix

The core agentic loop: run, read the failure, change the source, run again until green.

**Bridge defect this scenario is built to catch**: A non-zero exit or stderr-heavy tool_result is dropped or mis-flagged, so the model never learns the run failed and stops early.

Judged on:
- Bash was used to run the suite.
- The first run came back failing and the session continued anyway.
- The test file is byte-for-byte unchanged.
- The runner re-runs the suite itself afterwards and it exits 0.

### `v04-shell-ops` — Background shell and git workflow

Long-running processes and version control, the two shell workflows that outlive a single command.

**Bridge defect this scenario is built to catch**: A backgrounded shell's handle is lost across turns, so the model never sees it finish and the process is orphaned.

Judged on:
- A long-running process was started and watched to completion.
- The tick log reached at least three lines.
- git log shows exactly the requested commit subject.
- No ticker process survives the slot.

### `v05-multi-step` — Four-step plan across file types

Holding a four-step plan over one turn and landing every step, across a source file, a plain text file, a new markdown file and a Jupyter notebook.

**Bridge defect this scenario is built to catch**: The plan is lost as the tool loop lengthens, so early steps land and the last ones are silently dropped.

Judged on:
- All four changes are present on disk.
- The notebook still parses as a valid nbformat 4 document.
- No step was reported done without the file backing it.

### `v06-subagent` — Subagent delegation

Handing work to a project-defined subagent and using what comes back.

**Bridge defect this scenario is built to catch**: The subagent's own tool loop runs on a nested session; its final report can be lost at the handoff, leaving the parent to invent an answer.

Judged on:
- The project-defined agent is advertised in the init event.
- The Task tool was invoked against that agent.
- A tool_result came back for the delegation.
- The final answer names the files only the delegated search could have found.

### `v07-mcp-playwright` — MCP browser automation, headless

Third-party capability arriving over MCP and being used for real: a headless Chrome driven through @playwright/mcp.

**Bridge defect this scenario is built to catch**: MCP tool schemas are rewritten or namespaced differently on the way through, so the model cannot call them or calls them with the wrong shape.

Judged on:
- The playwright MCP server is connected in the init event.
- At least one mcp__playwright__* tool was called.
- The answer carries the token that only exists in the served page's DOM.

### `v08-hooks-memory` — Hooks, memory, commands and skills

Everything the project configures around the model: CLAUDE.md rules, hooks that observe and deny, custom commands and skills.

**Bridge defect this scenario is built to catch**: A hook denial arrives as an ordinary tool_result instead of a refusal, so the model treats a blocked action as done.

Judged on:
- The CLAUDE.md rule was obeyed: the record landed at the path the project mandates.
- The PreToolUse hook fired and left its log.
- The forbidden command was denied and never ran.
- The custom command and skill are advertised in the init event.

### `v09-session-resume` — Session resume across processes

Closing the laptop and picking the same conversation back up: a second process must inherit the first one's context.

**Bridge defect this scenario is built to catch**: Session state is keyed on the upstream connection, so resuming re-opens an empty conversation that answers from nothing.

Judged on:
- The resumed process reports the same session id.
- It recalls the planted build id.
- It used no file-reading tool: the answer came from conversation context.

### `v10-long-context` — Long context retrieval and reasoning

Pulling two facts from far apart in a large context and combining them, which is what long context is actually for.

**Bridge defect this scenario is built to catch**: Context is silently truncated upstream, so the model answers confidently from the half it still has. The corpus is carried in the prompt, not read from disk, so nothing but the transport can deliver it.

Judged on:
- The arithmetic answer is exactly right, which needs both facts.
- Reported input usage reflects the whole corpus, not a truncated prefix.
- The answer came from the prompt itself: no file-reading tool was used.

## Coverage

The ten scenarios exercise **90.7%** of the Claude Code core-feature inventory (weight 78/86). That number is computed from the inventory in `scripts/verify/features.mjs` and each scenario's `covers` list, not asserted in prose.

### Not covered (the honest remainder)

- `thinking` (weight 2) — Extended thinking / reasoning blocks
- `webfetch` (weight 2) — WebFetch / WebSearch
- `tui` (weight 2) — Interactive TUI affordances (plan picker, /rewind)
- `compaction` (weight 2) — Automatic context compaction

### Tools this build does not offer (excluded from the denominator)

Claude Code 2.1.278 does not provide `TodoWrite`, `BashOutput`, `KillShell`. This was measured by asking a model to call them directly; it answered that they are unavailable and reached for a workaround. That is the CLI's boundary rather than a bridge defect, so they count neither as covered nor as missed and leave the denominator entirely.

- `bash-background` (weight 2, `BashOutput` needs) — Background shells and output polling
- `todo` (weight 2, `TodoWrite` needs) — TodoWrite task tracking
